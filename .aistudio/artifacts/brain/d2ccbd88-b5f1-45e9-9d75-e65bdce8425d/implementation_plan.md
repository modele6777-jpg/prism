# 오늘의 타로 결과 본문 및 핵심 3줄 요약 중복 출력 제거 계획

오늘의 타로 결과 표시 시 본문 전체가 2회 연속 중복으로 출력되거나 상단 그래픽 카드와 하단 본문에 핵심 3줄 요약이 겹쳐서 나타나던 현상을 근본적으로 해결합니다.

### User Review & Confirmed Decisions

> [!IMPORTANT]
> - **본문 중복 2회 출력 방지**: 스트리밍 폴백 및 재시도 과정에서 전체 텍스트가 중첩 결합(A + A)되던 스트림 청크 수신 로직과 정규식 감지 범위를 유니코드 전 이모지(`\p{Extended_Pictographic}`)로 전면 확장하여 본문 반복을 원천 차단합니다.
> - **핵심 3줄 요약 위치 단일화**: 리딩 최상단 프리미엄 그래픽 카드(`TarotSummaryGraphicCard`)에만 핵심 3줄 요약을 단 1회 렌더링하고, 하단 상세 본문(`Streamdown`)에서는 선행/후행 요약 블록을 100% 제거하여 1단계부터 5단계까지 깔끔한 상세 리딩만 표시합니다.

---

### 1. 현상 분석 및 중복 원인 (Root Cause)

1. **스트리밍 재시도 및 비스트림 폴백 시 청크 중복 결합 (`src/pages/TrinityApp.tsx`)**:
   - `invokeLLMStream` 실행 중 일시적인 연결 지연이나 폴백 발생 시 전체 텍스트가 단일 청크로 다시 전달되는데, 기존 중복 방지 조건문의 1단계 헤더 정규식(`[✨👑💎🌟⚡🏆💰🌅💌☯️🛤️🕯️☀️🧭]`)이 특정 이모지(`☀️` 바리에이션 셀렉터, `🍃`, `🌱`, `💧`, `⚖️` 등)를 인식하지 못해 기존 본문 뒤에 전체 결과가 통째로 덧붙여짐 (`finalResponse += chunk`).
2. **중복 제거 유틸리티의 제한된 이모지 화이트리스트 (`src/lib/tarotSummaryUtils.ts`)**:
   - `deduplicateReadingText`의 1단계 중복 분할 정규식이 하드코딩된 이모지만 검사하여, 스프레드 테마별 다양한 이모지가 사용된 오늘의 타로 리딩의 중복 텍스트(A + A)를 온전히 걸러내지 못함.
3. **선행 핵심 3줄 요약 제거 조건의 인덱스 예외 (`stripSummaryFromTarotText`)**:
   - AI 응답이나 로컬 오라클 본문 맨 첫머리(index 0)에 `[핵심 3줄 요약]` 또는 `### [핵심 3줄 요약]`이 위치할 경우, `firstHeaderMatch.index > 0` 조건으로 인해 선행 요약 블록이 본문에서 잘리지 않고 `<Streamdown>` 본문에 그대로 남아서 상단 카드와 하단 본문 모두에 중복 노출됨.

### 2. 기술 아키텍처 및 개선 방안 (Technical Architecture)

```
[오늘의 타로 AI 스트리밍 / 로컬 오라클 생성]
               │
               ▼
[1. 청크 결합 단계 (TrinityApp.tsx)]
   - 유니코드 확장 이모지 정규식(\p{Extended_Pictographic}) 및 1단계 헤더 감지 강화
   - 재시도 또는 전체 텍스트 수신 시 누적 텍스트 덮어쓰기 (중복 누적 원천 방지)
               │
               ▼
[2. 본문 디듀플리케이션 엔진 (tarotSummaryUtils.ts)]
   - deduplicateReadingText: 1단계 헤더(### ... 1.) 2회 이상 출현 시 첫 번째 온전한 리딩만 보존
   - 텍스트 2분할(A + A) 반복 구조 자동 감지 및 단일화
               │
               ▼
[3. 요약 분리 & 화면 배치 단일화]
   - 상단: TarotSummaryGraphicCard (핵심 3줄 요약 전용 그래픽 카드 1회만 표시)
   - 하단: Streamdown 본문 (stripSummaryFromTarotText로 선행/후행 요약 100% 제거, 1~5단계 순수 본문만 표시)
```

1. **청크 수신 핸들러 강화 (`src/pages/TrinityApp.tsx`)**:
   - `onChunk` 수신 시 `chunk` 내에 1단계 헤더나 `[핵심 3줄 요약]`이 포함되어 있고 `finalResponse`에도 이미 해당 내용이 존재하면 `finalResponse += chunk` 하지 않고 온전히 최신 청크로 교체(`finalResponse = chunk`).
2. **정밀 중복 제거 엔진 고도화 (`src/lib/tarotSummaryUtils.ts`)**:
   - `section1Regex`를 `/(?:\r?\n|^)\s*###\s*(?:\p{Extended_Pictographic}|\S)*\s*1[\.\s][^\r\n]*/gui`로 전면 개편하여 모든 타로 스프레드 이모지 및 마크다운 헤더를 완벽 감지.
   - `[핵심 3줄 요약]` 블록이 2개 이상 포함된 경우 첫 번째 완전한 블록 이후의 복제본을 즉시 제거.
3. **선행/후행 요약 블록 완전 분리 (`stripSummaryFromTarotText`)**:
   - 텍스트 시작부의 `[핵심 3줄 요약]`이나 `### [핵심 3줄 요약]` 블록을 본문 1단계 헤더 직전까지 깨끗하게 잘라내어 `<Streamdown>` 본문에는 오직 1단계부터 5단계까지의 깊이 있는 스토리텔링 리딩만 표시되도록 정비.
4. **`TodayTarotNarrationModal.tsx` 및 `TrinityApp.tsx` 뷰 정합성 점검**:
   - 모달과 메인 화면 모두 상단 요약 카드와 하단 본문 간에 불필요한 중복이 일체 발생하지 않도록 렌더링 파이프라인 동기화.

---

### 3. 검증 계획

- **오늘의 타로 리딩 생성 테스트**: 오늘의 타로 카드 뽑기 후 상단에 3줄 요약 카드 1회, 하단에 1~5단계 본문 1회만 깔끔하게 나오는지 확인.
- **스트리밍 재시도 및 폴백 시뮬레이션**: 전체 텍스트 수신 시 본문 내용이 2회 반복되지 않는지 검증.
- **음성 낭독 연동 확인**: 전체 낭독 및 요약 낭독 시 중복된 문장을 읽지 않고 지정된 텍스트만 자연스럽게 낭독되는지 확인.
- **빌드 및 린트 검증**: `npm run lint` 및 `npm run build`를 통한 빌드 무결성 확인 후 배포.
