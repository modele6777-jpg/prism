# 타로 결과 연속 추가 질문 및 제외 덱 추가 리딩 시스템 구현 계획

타로 리딩 결과 화면에서 이미 뽑힌 카드를 78장 덱에서 완전히 제외한 상태로, 사용자가 추가 질문을 입력하고 직접 휠을 돌리거나 자동으로 추가 카드를 뽑아 연속 리딩을 시간순 타임라인 형태로 누적 열람할 수 있는 심층 타로 확장 시스템을 구현합니다.

---

## User Review & Critical Decisions

> [!IMPORTANT]
> 사용자가 Phase 1 질문에서 확정한 선택 사항을 바탕으로 시스템을 설계합니다.

- **[확정] 추가 질문 카드 뽑기 방식**: **직접 뽑기와 자동 뽑기 중 매번 선택하기**
  - 추가 질문 제출 시 또는 입력창 상단에서 `[직접 카드 고르기 (휠 회전)]`과 `[원터치 즉시 뽑기 (자동)]` 액션을 제공합니다.
  - 직접 고르기를 선택하면 남은 카드들로만 구성된 타로 휠 모달이 열려 직접 손으로 돌려 1장을 뽑으며, 자동 뽑기를 누르면 셔플 사운드와 함께 즉시 1장이 선택됩니다.
- **[확정] 추가 질문 및 리딩 결과 배치**: **기존 결과 하단에 질문별 타임라인 카드로 누적 표시**
  - 메인 리딩 결과 바로 아래에 시간순 타임라인(`FollowUpTarotTimeline`)이 구성되어, "추가 질문 #1", "추가 질문 #2"가 카드의 일러스트/키워드/해설과 함께 매끄럽게 누적 표시됩니다.
- **[확정] 추가 질문 입력 방식**: **자유 텍스트 입력창과 AI 추천 질문 칩 함께 제공**
  - 현재 리딩된 카드들의 상징 및 고민 주제에 맞춘 지능형 추천 질문 칩(3~4개)을 상단에 띄우고, 하단에는 자유 질문을 작성할 수 있는 텍스트 인풋과 전송 버튼을 배치합니다.

## 1. Overview & Core Concept

- **목적**: 1회성 리딩으로 끝나지 않고, 리딩 결과를 본 사용자가 "그렇다면 앞으로 어떻게 행동해야 할까?", "상대방의 속마음은 어떨까?"와 같은 세부 궁금증을 자연스럽게 이어갈 수 있도록 지원합니다.
- **덱 무결성 보장 (No Duplicate Draws)**:
  - 초기 스프레드에서 뽑힌 카드(예: 3장)는 물론, 이전 추가 질문에서 뽑힌 모든 카드(예: 1장, 2장...)가 78장 덱에서 완전히 제외됩니다.
  - 남은 덱(예: 75장 -> 74장 -> 73장...)의 카드들로만 타로 휠이 렌더링되거나 무작위 추첨되어, 실제 오프라인 타로 세션처럼 중복 카드가 나오지 않는 완벽한 덱 카운팅을 유지합니다.
- **연속 진행 (Infinite Depth)**:
  - 추가 리딩이 완료된 후에도 계속해서 추가 질문을 진행할 수 있으며, 남은 덱 수량이 실시간으로 표시됩니다.

## 3. Key Components & Implementation Details

### A. 잔여 덱 관리 및 상태 구조
- **상태 관리**:
  - `drawnCardIds`: 초기 스프레드 선택 카드 ID 목록 + 각 추가 질문에서 뽑힌 카드 ID들의 합집합.
  - `remainingDeck = useMemo(() => TAROT_DECK.filter(c => !drawnCardIds.includes(c.id)), [drawnCardIds])`.
  - `followUpEntries: Array<{ id: string; question: string; card: TarotCard; reversed: boolean; reading: string; createdAt: number }>`
- **타로 휠 모달 연동**:
  - `showFollowUpWheelModal: boolean` 상태 지원.
  - 사용자가 `[직접 카드 고르기]` 선택 시, 기존의 360도 무결점 `TarotSpread` 모달을 호출하되, `deckSource={remainingDeck}`, `maxCards={1}`, `concern={currentFollowUpQuestion}`을 전달하여 남은 카드들로만 원형 휠을 구성.

### B. 추가 리딩 AI 스트리밍 프롬프트 설계
- 시스템 프롬프트:
  - 역할: 이전 리딩과 고민 맥락을 모두 기억한 상태에서 새로 뽑힌 추가 카드의 상징을 연계하여 질의에 단도직입적으로 답하는 트리니티 타로 마스터.
  - 컨텍스트 주입:
    - 최초 질문: `${tarotConcern}`
    - 최초 선택 카드들: `${drawnCards.map(c => c.nameKo).join(', ')}`
    - 최초 리딩 요약: `${tarotResult.slice(0, 400)}`
    - 이전 추가 질의응답 이력
    - 새로 뽑힌 카드: `${newCard.nameKo} (${newCard.reversed ? '역방향' : '정방향'})`
    - 이번 추가 질문: `${followUpQuestion}`

### C. UI/UX 디자인 (Universal Frontend Design 준수)
- **Zero-Pill & 미니멀 타이포그래피**:
  - 메타데이터(남은 덱 장수, 카드 번호, 시간)는 박스형 알약 칩이 아닌 세련된 텍스트와 점 분리자(`·`)로 배치.
  - 추가 카드는 금빛 은은한 테두리와 호버 확대 인터랙션 지원.
- **햅틱 및 사운드 피드백**:
  - 추가 카드 선택 시 `playAudioHaptic('card_draw')`, 스트리밍 완료 시 성공 차임 연동.
- **모바일 최적화**:
  - 모바일 터치 규격(최소 44px 터치 타겟)을 준수하고, 키보드가 올라올 때 입력창이 가려지지 않도록 세심한 레이아웃 설계.

## 4. Phased Implementation Roadmap

### Phase 1: 잔여 덱 연동 및 상태 파이프라인 구축
- 초기 스프레드 카드와 추가 질의응답 카드를 통합 관리하는 `drawnCardIds` 및 `remainingDeck` 상태 설계.
- `followUpEntries` 데이터 모델 정의.

### Phase 2: 추가 질문 입력바 및 지능형 추천 질문 생성
- `FollowUpTarotInputBar` 구현: 자유 질문 인풋, 3~4개의 맥락 기반 추천 질문 칩, `[직접 뽑기]` / `[자동 뽑기]` 분기 버튼.
- 입력창 하단에 현재 잔여 덱 현황(`남은 덱: N장`) 표시.

### Phase 3: 잔여 덱 전용 타로 휠 연동 & AI 스트리밍
- `[직접 뽑기]` 시 `TarotSpread`에 `deckSource={remainingDeck}`를 주입하여 1장 선택 팝업 연동.
- `[자동 뽑기]` 시 셔플 애니메이션과 함께 즉각 무작위 1장 추출.
- 카드가 선택되는 즉시 이전 컨텍스트를 계승한 `invokeLLMStream`을 호출하여 실시간 타이핑 스트리밍 구현.

### Phase 4: 타임라인 렌더링 카드 및 연속 리딩 고도화
- 각 추가 질문과 카드가 누적되는 `FollowUpTarotTimeline` 컴포넌트 렌더링.
- 리딩 텍스트 내 TTS 재생 버튼 및 카드 확대 줌 모달 연계.
- 전체 리딩 결과 저장 및 공유 시 추가 리딩 데이터도 포함되도록 연동.

### Phase 5: 검증 및 릴리즈 규칙 준수
- `npm run lint` 및 `npm run build` 검증.
- `package.json`, `public/version.json`, `public/changelog.json` 버전 갱신 및 커밋.
